# SPK СЛОТЫ Frontend

Презентационный веб-интерфейс для проведения розыгрышей, разработанный на **Nuxt 4 (Vue 3 / JavaScript)** с использованием **Tailwind CSS** и **GSAP** для плавной анимации колеса фортуны.

---

## 🛠 Стек технологий

* **Фреймворк:** Nuxt 4 (SPA-режим, JavaScript)
* **Стилизация:** Tailwind CSS
* **Стейт-менеджмент:** Pinia (`@pinia/nuxt`)
* **Анимации:** GSAP (вращение колеса)


* **Утилиты:** VueUse, `qrcode.vue` (генерация QR), `canvas-confetti` (эффекты на финальном экране)



---

## Как запустить проект

### 1. Установка зависимостей

Убедитесь, что у вас установлен Node.js, затем в корне проекта выполните:

```bash
npm install

```

### 2. Настройка подключения к бэкенду

По умолчанию фронтенд использует встроенный мок-сервер Nitro (в папке `server/`), что позволяет запустить проект с мок сервером для теста.

Если нужно подключить реальный Python-бэкенд отредачить нукст конфиг (там понятно)



### 3. Запуск в режиме разработки

```bash
npm run dev

```

Сайт будет доступен по адресу: `http://localhost:3000`

### 4. Сборка для продакшна

```bash
npm run build

```

## API (Эндпоинты, которые ждет фронт)

Фронтенд ожидает от бэкенда следующие эндпоинты (с префиксом `/api`):

### 1. Получение конфигурации (ссылка на ТГ-бота)

* **GET** `/api/config`
* **Описание:** Вызывается при старте приложения и при возврате к новому розыгрышу для генерации актуального QR-кода.
* **Ответ (JSON):**
```json
{
  "botUrl": "https://t.me/spk_raffle_bot?start=session1"
}

```


*(Фронтенд также поддерживает ключи `"url"` или `"link"` в объекте ответа).*
* **POST** `/api/config` *(Опционально)*
* **Описание:** Отправляет измененную ссылку на бэкенд, если администратор перенастроил её через модальное окно на фронте.
* **Тело запроса:**
```json
{
  "botUrl": "https://t.me/new_bot_link"
}

```



---

### 2. Получение списка участников

* **GET** `/api/participants`
* **Описание:** Фронтенд запрашивает этот список каждые 2 секунды, пока открыт экран QR-кода и пока колесо еще не начало вращаться (чтобы участники динамически отображались на секторах).
* **Ответ (JSON):**
```json
{
  "participants": [
    { "id": 1, "number": 77, "name": "Алексей" },
    { "id": 2, "number": 100, "name": "Мария" }
  ]
}

```


*(Фронтенд также корректно обработает, если бэкенд вернет просто массив `[...]`).*

---

### 3. Выбор победителя

* **POST** `/api/winner`
* **Описание:** Вызывается в момент, когда администратор нажимает пробел на экране колеса. Бэкенд должен случайным образом выбрать победителя из текущей базы. После этого фронт блокирует опрос участников и запускает плавное вращение колеса до нужного сектора.


* **Ответ (JSON):**
```json
{
  "winner": {
    "id": 2,
    "number": 100,
    "name": "Мария"
  }
}

```



---

### 4. Закрытие сессии / Сброс розыгрыша

* **POST** `/api/session-close`
* **Описание:** Вызывается по завершении розыгрыша (на экране победителя при нажатии пробела). Сигнализирует бэкенду очистить текущих участников, после чего интерфейс автоматически возвращается к экрану регистрации с QR-кодом.
* **Ответ (JSON):**
```json
{
  "status": "ok"
}

```
